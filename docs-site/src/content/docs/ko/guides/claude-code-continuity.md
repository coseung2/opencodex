title: Claude Code 대화 이어가기
description: 모델 연결 후 추론 옵션과 도구 실행 뒤 대화가 이어지는지 확인합니다.
---

모델이 목록에 나타나는 것만으로 추론 옵션이나 도구 실행까지 정상 동작한다고 볼 수는 없습니다. 연결을 바꾼 뒤에는 짧은 대화뿐 아니라 파일을 읽고 그 결과로 작업을 계속하는 흐름도 확인하세요.

## 추론 옵션

연결된 모델의 지원 강도와 겹치는 기존 기본 모델의 메뉴를 사용합니다. 지원 정보가 없는 모델에 임의로 추론 옵션을 만들지는 않습니다. CLI의 `cc` 카탈로그와 대체 bootstrap 목록은 Desktop의 `ccd`·`code` 목록과 별개입니다.

메뉴가 예전 상태라면 새 Claude Code 세션에서 모델 카탈로그를 갱신하세요. CLI 카탈로그 캐시는 앱 재시작 뒤에도 남을 수 있으므로, 예전 목록만으로 현재 설정을 판단하지 마세요.

## 도구와 스킬 실행 뒤 작업 계속하기

Claude의 기본 연결 방식에서는 이전 지시와 대화를 서버에 남겨두고, 새 도구 결과만 보낼 수 있습니다. 다른 모델로 전달하는 경로는 `thread_unsupported_request` 응답으로 Claude가 전체 대화를 다시 보내도록 합니다. 이를 통해 도구 실행 뒤 원래 작업을 잃고 새 질문처럼 처리하는 문제를 막습니다. 토큰 계산에도 같은 처리를 적용하며, 원래 Anthropic으로 직접 전달하는 대화는 기존 이어쓰기 방식을 유지합니다.

ToolSearch 결과의 도구 이름을 보존하며, 함수 도구의 선택 매개변수를 임의로 필수 매개변수로 바꾸지 않습니다.

Notch의 전용 연결은 다른 모델의 대화 이어쓰기 요청에 대해 로컬에서 전체 대화 재전송을 알립니다. 릴레이 요청은 길이가 정해진 본문으로 전송해, 서버의 빠른 응답을 연결 실패로 잘못 처리할 가능성을 줄입니다. 기본 Anthropic 대화의 경로는 유지합니다.

Kiro의 최종 답변은 생성되는 답변 조각부터 표시합니다. 작업 진행 문구는 구분할 수 있을 때까지 보류하며, 완료 여부와 잘못된 데이터 검증은 유지합니다. 일부 답변을 보여준 뒤 오류가 나면 같은 답변을 자동 재전송하지 않습니다.

전용 연결은 Claude Code의 검색 전용 보조 요청을 지정된 OpenAI `gpt-6-luna` 모델로 보냅니다. 검색 도구 선택과 출처 목록을 전달하며 Anthropic 구독 인증값을 보내지 않습니다. 일반 모델 목록에 Luna를 추가하지 않아도 현재 연결에 묶인 보조 요청 경로를 사용할 수 있습니다. 이는 기본적으로 OpenAI를 사용하는 OCX의 일반 웹 검색 사이드카와 별개입니다.

추가 도구가 없는 기본 Haiku의 WebFetch 분석, JSON 세션 제목 생성, 완료된 도구 실행의 짧은 요약도 전용 요청 형태가 확인되면 Luna로 보냅니다. 다운로드와 권한 확인은 Claude가 유지합니다. 식별하지 못한 형태나 새 버전의 요청은 기존 경로를 유지하며 Haiku 전체를 교체하지 않습니다. 안전 검사, 일반 대화, 모델이 지정된 서브에이전트는 그대로입니다. 대화 압축과 메모리 추출을 일괄 Luna로 강제하지 않았습니다.

연결된 모델에서는 기본적으로 큰 `claude-api` 참고 자료 묶음을 생략합니다. Skill 도구에 예방 안내를 전달하고, 그래도 실행된 경우 기본 인사로 돌아가지 말고 기존 작업을 계속하도록 안내합니다. 자료를 유지하려는 경우에만 `claudeCode.blockedSkills`를 빈 배열로 설정하세요.

Responses 모델의 숨겨진 추론은 화면에 노출하지 않고 다음 턴으로 전달할 수 있습니다. 실제 요청 주소·모델·인증 정보가 일치하는지 검증하며, 연결이나 인증이 바뀌거나 프록시가 재시작되면 해당 내부 상태는 재사용하지 않습니다. 화면에 보이는 대화 이력은 유지됩니다. 다른 제공자의 내부 상태를 기본 Anthropic 대화에 보내지 않습니다.

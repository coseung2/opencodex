# OpenCode Go enabled models rejected requests without a session ID

- Date: 2026-09-25 (Asia/Seoul)
- Symptoms: Every OpenCode Go model enabled in the VM Notch catalog returned HTTP 400 with `MissingSessionID` when invoked through a plain OpenAI-compatible Responses request.
- Impact: All seven enabled OpenCode Go models appeared selectable but failed before generation for clients that did not send Codex or OpenCode conversation headers.
- Evidence: The VM root catalog at `~/.codex/opencodex-catalog.json` contained seven OpenCode Go rows with `visibility: "list"`. A bounded authenticated probe of only those rows reproduced the same missing `x-opencode-session` rejection on all seven.
- Confirmed cause: The proxy generated the required opaque header only when an inbound parent, thread, session, or OpenCode session header existed. OpenCode Go now requires the header even for clients without those identifiers.
- Response: Generate a random opaque runtime-only request lane when no stable caller lane exists, while preserving stable hashed affinity for clients that provide conversation identity and preserving explicit operator headers.
- Recovery verification: Focused session/failover tests passed (19 passed, 0 failed), along with type checking, privacy scanning, `git diff --check`, and the full 11-batch test suite (0 failed). The installed VM tree passed a Bun link build, and `opencodex-proxy.service` restarted once on PID 145595 with `NRestarts=0`; both loopback and public health checks returned version `2.8.0-cs.34`. Repeat probes no longer returned `MissingSessionID`: DeepSeek V4.1 Flash, both MiMo V2.6 models, Space Bunny, and Muse Spark completed. GPT-6 Luna and Grok 4.7 reached OpenCode Go but returned upstream `server_is_overloaded` after three sequential retries each. Direct Bun probes with both configured provider keys confirmed that OpenCode Go still listed both IDs but returned HTTP 503 `Upstream request failed: Endpoint is unavailable.` for generation.
- Follow-up: Keep the fallback request-scoped; clients that need cross-turn provider affinity should send one of the supported conversation headers. OpenCode Go must restore the Luna and Grok backing endpoints, or stop listing them, before those enabled rows can be considered usable.

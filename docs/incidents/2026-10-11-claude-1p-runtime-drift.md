# Claude 1P source/runtime drift

- Date/timezone: 2026-10-11, Asia/Seoul; investigation and rollout around 06:58-07:12 KST.
- Symptoms/impact: routed model names appeared in Claude's Code picker without reasoning controls. The user also reported task-context resets after a repository tool call; that separate behavior is not conclusively diagnosed by this incident.
- Confirmed cause: the Windows companion ran an older installed source snapshot, and the authoritative VM runtime did not publish `firstPartyCatalog`. Notch's legacy metadata conversion therefore supplied an empty effort list for all 17 rows, and the installed picker removed their thinking controls. Repository-only test/commit completion had not updated either live runtime.
- Evidence: live VM `/api/claude-desktop` initially lacked `firstPartyCatalog`; local bound state had 17 models and zero nonempty effort lists. Installed companion files differed from repository source, with the new presentation and native-reasoning modules absent. Session metadata did contain the `opencodex` cwd and a PowerShell tool call, so missing folder selection was not established as the conversation failure.
- Response: validated a nine-file VM patch against the running installation, checked candidate and installed module graphs, backed up original files, restarted only the named user proxy service, and verified health/catalog recovery. Backed up and replaced the dedicated Windows companion runtime, restarted its verified supervisor/worker, and retained the detached data relay. Backed up and invalidated only generated `cc`/`ccd` model catalog caches.
- Recovery: VM and local bound state now publish 17 models, with supported effort lists for five. The Windows worker is ready on all three expected ports. Claude settings remained byte-identical and the detached relay retained its PID. Focused tests passed 63 cases and TypeScript validation passed before rollout.
- Scope/remaining verification: no credential rotation, provider changes, publication, push, or PC shutdown. No paid model canary was submitted. The user will restart Claude and verify its real picker and multi-turn conversation. Do not claim the reported conversation reset fully resolved from metadata or fixture checks alone.
- Prevention: finish live installed-path, metadata and app-reload checks before describing a repository patch as a completed user-facing fix. Keep backups and the per-file deployment manifest for rollback.

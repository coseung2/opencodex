# Stale provider model IDs caused repeated 404 responses

- Date: 2026-09-25 (Asia/Seoul)
- Symptoms: Requests routed through the production proxy returned upstream 404 responses for Google Antigravity `gemini-3.7-flash`; historical VM usage also showed repeated OpenRouter `stealth/ox-alpha` 404 responses.
- Impact: Antigravity's default Flash route failed before generation, and the static OpenRouter catalog continued to offer a closed preview model that could no longer be invoked.
- Timeline: The production VM was confirmed healthy on OCX `2.8.0-cs.34`, but its Antigravity adapter sent the picker ID `gemini-3.7-flash` directly. Repository history contained a later upstream fix and live evidence that the base ID returns 404 while `gemini-3.7-flash-tiered` returns 200. VM usage history contained 18 Antigravity 3.7 404s and 370 OpenRouter Ox Alpha 404s. Other observed 404s for `gpt-6-sol` were investigated separately and retained because the same production history contained substantially more successful calls across several accounts.
- Evidence: The installed runtime used `const GEMINI_FLASH_CURRENT = "gemini-3.7-flash"` as its wire ID. Upstream commit `a70bb78d4` records live 404/200 probes for the base/tiered Google IDs. Upstream commit `328931265` records Ox Alpha as a closed stealth window. Production history also contained successful `gpt-6-sol` and `gpt-6-luna` calls, ruling out a global retirement of those models.
- Confirmed cause: Stable picker IDs and provider wire IDs had diverged after Google's rename, while a time-limited OpenRouter model remained in the static fallback catalog after its serving window closed.
- Response: Resolve Gemini 3.6 and 3.7 base IDs to their `-tiered` wire IDs only at dispatch, resolve Antigravity 3.7 and retired aliases to the CCA tiered ID, and remove Ox Alpha only from the OpenRouter static catalog.
- Recovery verification: The four focused suites passed 86 tests, followed by type checking, privacy scanning, `git diff --check`, and the full 11-batch test suite with zero failures. The three runtime files were backed up and overlaid onto the complete installed `2.8.0-cs.34` package only after its Bun link check passed. One supervised restart changed the service PID from 1959845 to 21495; internal and public health returned 200 on the same new PID, and systemd remained `active/running` with `NRestarts=0` after the stability wait. An authenticated production `gemini-3.7-flash` Responses request returned HTTP 200 with a `completed` terminal and the expected marker, while authenticated `/v1/models` returned 200 without `openrouter/stealth/ox-alpha`.
- Follow-up: Keep live-discovery providers authoritative where available, and require a dispatch-level regression when a provider keeps a stable picker name while renaming the accepted wire ID.

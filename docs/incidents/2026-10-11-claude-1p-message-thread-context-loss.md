# Claude 1P continuation context loss

- Date/timezone: 2026-10-11, Asia/Seoul.
- Symptoms: routed GPT could announce a repository task, execute one tool, then ask what the user wanted instead of continuing. Routed Kiro retried HTTP 500 after a tool turn.
- Evidence: the Kiro client error page contained the server's orphaned-tool-result exception. The native Responses adapter's existing orphan repair can instead turn an unpaired result into a new user message. Neither behavior restores a missing task prefix. The fork lacked the message-thread negotiation added upstream in `bf04176b67` (#5935 integrated through #5985).
- Confirmed implementation defect: the translated Messages path ignored a first-party `thread` object. A continuation can contain only the delta after a previous message, omitting system instructions, tools and older turns. Translating it as a stateless full request loses context. The exact wire body of the reported session was not persisted; do not treat that session-specific attribution as a captured-request proof.
- Response: ported upstream's `carriesMessageThread` detection and exact `thread_unsupported_request` response. Applied it to translated Messages and token-count endpoints after native Anthropic passthrough selection. Native Anthropic retains its thread objects unchanged. This is protocol negotiation, not an extra model instruction.
- Verification: adapted upstream regression tests pass. They reject both thread creation and continuation before invoking a provider, verify full-history resend preserves the original task and system prompt, and preserve genuine native Anthropic passthrough. Both direct VM probes and authenticated local HTTPS proxy -> detached relay -> VM probes return HTTP 400 with the exact fallback code on both endpoints; no paid inference was submitted by those probes. The installed Claude Code 2.1.295 binary contains that exact fallback code. TypeScript, privacy and documentation build checks pass.
- Rollout: preserved the current VM installation, staged a two-file hash-verified patch, backed up originals, checked module resolution, and restarted only the proxy user service. The first verification attempt used the management credential on an inference endpoint and rolled back automatically. Repeating with the established data credential verified the protocol and retained the patch. Local companion mirrors are kept in sync without changing login settings or the detached relay.
- Full suite: all 12 batches completed with 7,732 passing tests and zero failures.
- Remaining: the user's real Claude multi-turn interaction still requires confirmation; do not claim a fixture or synthetic protocol probe is user-visible success.
- Prevention: compare ingress protocol negotiation with upstream before proposing prompt-level workarounds; retain a tool-turn regression that tests original task retention, not just two successful HTTP responses.
